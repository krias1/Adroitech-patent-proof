# Codex Consumer Guide

This repository is the evidence/provenance stream for the clean Adroitech OS work in:

`https://github.com/krias1/Adroitech-Logic-Core`

## Division of labor

The proof stream handles exhaustive historical extraction, hashing, chronology, concept decomposition, provenance, public reproducibility, and P1-support mapping.

The proof stream is not a highlights reel. It is tasked with reviewing every recoverable artifact across the authorized source universe and assigning each source a documented disposition.

Codex should focus on making the clean Adroitech OS complete and new-customer-ready.

As proof extraction proceeds, each relevant concept is evaluated against the frozen P1 disclosure. The support map is updated during the same review pass rather than deferred until the end.

## How Codex should use this repository

Use the proof corpus to answer:

- What historical ethical rule or behavior exists that the clean OS may still be missing?
- Which skill or teaching practice appears repeatedly across the archive?
- Which concepts developed into later customer-safe policies?
- Which principles have strong, independently checkable provenance?
- Which ideas were superseded or refined and should not be copied literally?
- Which implementation or runtime records support a P1 mechanism?
- Which discovered material is classified as possible new matter rather than silently folded into P1?

When a proof record reveals a product-relevant omission:

1. verify the source record and its provenance;
2. identify the strongest/current customer-safe formulation;
3. implement the behavior or policy in the clean OS;
4. add or update acceptance tests;
5. keep historical proof mechanics out of the normal customer product surface.

## Source-coverage expectation

The proof extractor is responsible for the full recoverable source universe, including canonical Git history and preserved original pre-Git/non-Git rails such as Drive, Gemini/Six chats, Gmail, business Gmail, Dropbox, PDFs/decks, receipts, logs, builds, screenshots, device records, and other authorized originals.

Do not assume that absence from Git means absence from the historical record.

Do not assume that a repository mirror has the same provenance weight as the original external source.

## Do not

- duplicate the entire proof extraction effort;
- replace current customer-safe language with raw historical wording just because it is older;
- treat an inference field as a source fact;
- treat source-stated historical dates as Git-verified dates;
- copy archive-only founder context into customer runtime state;
- block product work waiting for the evidence corpus to be complete;
- treat the proof repository as amending P1;
- treat a later implementation as if it had automatically existed in the filed specification;
- discard a source merely because it appears repetitive or low significance before review.

The proof stream leads discovery and evidence mapping.

Codex leads productization.
