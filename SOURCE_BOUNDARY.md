# Source Boundary — Public Proof vs. Private Upstream Evidence

## Public reviewer contract

This repository is the reviewer-facing evidence system.

An outside scientist, patent professional, technical auditor, or AI reviewer should be able to work from the repository and its public or commit-pinned references without entering the maintainer's private accounts.

External reviewers are **not** instructed or authorized by this repository to access:

- the user's ChatGPT account, Library, or private chat history;
- private Gmail or business-Gmail accounts;
- private Google Drive or Dropbox accounts;
- local devices, private archives, or private credentials.

## Maintainer-side enrichment

The maintainer may consult private upstream sources to locate original records, recover chronology, resolve duplicates, confirm established facts, fill professional-dossier gaps, strengthen thesis history, or find technical evidence that belongs in the proof corpus.

Examples include prior ChatGPT Library uploads, private chats, private Drive documents, email attachments, photographs, screenshots, and local files.

That private inspection happens **upstream of the public corpus**.

The resulting repository contribution should contain only what is appropriate for the public proof system, such as:

- privacy-safe source identity;
- exact hashes or object identities where safe;
- timestamps and chronology classes;
- proof atoms;
- public-safe extracts or descriptions;
- implementation/test receipts;
- P1 support links;
- dossier evidence links;
- thesis evidence links;
- protected-personalization classifications when content itself should remain private.

## No hidden dependency

A public proof record should never amount to: "trust us because the real evidence is in a private ChatGPT account."

If a private source materially supports a public proposition, the proof project should preserve enough public-safe provenance or derived evidence for a reviewer to understand:

1. what type of source existed;
2. what proposition it supports;
3. how it fits the chronology;
4. what was withheld for privacy;
5. whether independent corroboration exists;
6. what remains non-public.

The private source may remain private. The evidentiary limitation must simply be explicit.

## Agent rule

An AI entering this repository should **not** attempt to discover or enter the maintainer's private source systems.

Use the repository's indexes, proof records, coverage reviews, P1 matrix, skill index, dossier evidence map, thesis evidence map, and public or commit-pinned sources.

Private-source enrichment is a curator function performed before or during repository maintenance, not a prerequisite imposed on the consumer.
